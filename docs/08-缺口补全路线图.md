| 要做什么 | 说明 |
|---|---|
| `backend/Dockerfile` | 基于 python:3.14-slim，装 requirements |
| `frontend/Dockerfile` | node 20 构建 → 产物交给 nginx |
| `.env.example` | 数据库地址、JWT、LLM Key 留空 |

## 7. 为什么是这个顺序

1. **先做能看见的**：个人中心与后台 CRUD 直接影响演示完整度，答辩老师最容易点。
2. **再做交付硬性的**：仓库、文档、PPT、4 表是「有没有交」的问题，不能拖到最后一天。
3. **RAG 放在文档之后**：它会改 AI 链路与接口，早做会让 D4 架构文档返工。
4. **社区/SSE 最后**：纯加分项，时间不够就在文档里说清取舍。

## 8. 每批的固定动作（不要漏）

1. 改代码 → 2. 补 pytest → 3. `pytest -q` + `npm run build` → 4. 回填 `docs/06` 状态与证据行号 → 5. 同步 README → 6. 汇报「阶段/文件/验证/风险」。

## 9. 明确不做的

| 项 | 原因 |
|---|---|
| R10「最多评论」排序改名 | 会推翻现有测试语义，收益仅文案一致 |
| Element Plus 按需引入 | 改动面大、易漏组件，当前 855 kB 不影响演示 |
| Redis / 多 worker | 课程项目单进程足够，引入后部署复杂度翻倍 |
| 真实支付 | 指导书只要求订单展示，不做支付闭环 |
