# 项目二：面向教育平台的智能体开发 —— 系统架构设计

> 版本：v1.0
> 日期：2026-11-24
> 适用范围：智学云课程学习 + 实习就业 + AI 学习助手平台
> 口径说明：本文接口清单、表结构、模块划分均以当前代码为准；接口总数 45 条路径 / 53 个操作，数据表 16 张。

## 1. 设计概述

| 项目 | 内容 |
|---|---|
| 架构风格 | 前后端分离 + 分层单体（Router → Service → ORM） |
| 后端 | FastAPI + Pydantic + SQLAlchemy 2.x，Python 3.14 |
| 前端 | Vue 3.5 + Vite 6 + Element Plus + Pinia + Vue Router + Axios + ECharts |
| 数据库 | MySQL 8.0（演示 / Docker）；SQLite（本地开发与测试） |
| 大模型 | OpenAI 兼容协议（DeepSeek 等）；无 Key 或调用失败自动降级 Mock |
| 检索增强 | 课程资料字符 bigram + TF-IDF，按课程范围召回 Top-3，回答带章节引用 |
| 部署 | 开发双进程；演示 Docker Compose（mysql + backend + nginx，8080:80） |

### 1.1 设计原则

- 关注点分离：Router 只做参数、鉴权与响应编排；业务规则集中在 Service；数据访问由 ORM 完成。
- 配置外置：数据库、JWT、LLM、CORS 全部走环境变量，代码不硬编码密钥。
- 可降级：LLM 不可用时走 Mock；课程资料不足时正常回答但不强行引用。
- 可测试：接口用 TestClient 集成测试；测试库独立，不污染演示库。
- 可迁移：SQLite 与 MySQL 双兼容；Docker 一键部署，本地零依赖可跑。

## 2. 总体架构

    浏览器（Vue3 SPA）
       │ RESTful JSON + JWT
       ▼
    Nginx（静态资源 dist，/api 反向代理）
       │
       ▼
    FastAPI 应用
       ├── routers：auth / users / courses / jobs / ai / admin / notifications / meta
       ├── services：llm 网关 / mock_engine / prompts / notifications / rag
       ├── core：config / database / security / deps / utils
       └── ORM（SQLAlchemy）──► MySQL 8.0 或 SQLite
                                  │
                                  └── LLM API（OpenAI 兼容）／Mock 引擎

请求链路：浏览器 → nginx（或 Vite 代理）→ FastAPI Router → 依赖注入（JWT / DB）→ Service / ORM → 统一响应 `{code,message,data}`。

### 2.2 关键设计决策

| 决策 | 备选 | 选择理由 | 代价 |
|---|---|---|---|
| FastAPI | Django / Flask | 自动 OpenAPI、Pydantic 校验、轻量 | 需自行实现后台管理接口 |
| SQLAlchemy 双库 | 仅 MySQL | 本地 SQLite 开箱即跑，演示可切 MySQL | 需规避方言差异 |
| JWT 无状态鉴权 | Session | 前后端分离适配，水平扩展简单 | 无法主动踢下线 |
| PBKDF2 自实现 | passlib / bcrypt | 标准库零编译依赖，兼容 Python 3.14 | 参数需自行维护 |
| LLM 网关 + Mock | 直连厂商 SDK | 厂商可替换，演示不依赖网络 | 多一层封装 |
| 字符 bigram + TF-IDF | 向量库 / embedding | 离线可跑、零外部依赖、可解释 | 语义泛化弱于向量检索 |
| 前端预构建 dist | 容器内 npm 构建 | 规避代理环境 npm 崩溃，构建稳定 | 重建前需先 `npm run build` |

## 4. 接口设计

### 4.1 规范

- 基路径 `/api`；JSON 请求/响应；时间为 ISO 8601。
- 响应统一为 `{code, message, data}`；`code=0` 表示成功。
- 错误码：40001 参数校验、40101 未登录/凭证错误、40301 无权限、40401 资源不存在、40901 冲突、50001 服务器错误。
- 分页：`page` 默认 1，`page_size` 默认 12、最大 50；返回 `{items, total, page, page_size}`。
- 鉴权：`Authorization: Bearer <JWT>`；JWT 载荷含 `sub`、`role`、`exp`，有效期默认 7 天。
- 角色：`student`、`teacher`、`admin`；教师课程操作按 `teacher_id` 做资源归属校验。

响应：

      "code": 0,
      "data": {

        "course_id": 1,

### 4.4 RAG 实现口径

- 资料入库：`course_materials` 保存课程、章节、标题、正文、关键词。
- 召回：仅检索当前 `course_id` 的资料；中文按 2-gram、英文/数字按 token，计算 TF-IDF 相关度，取 Top-3。
- 注入：检索结果作为「课程资料参考」拼入 System Prompt；无资料时填「（无匹配资料）」。
- 引用：回答末尾追加「参考：《课程》第 X 章《章节》」；多段资料按「；」合并并去重。
- 降级：无 Key 或在线失败走 Mock；Mock 回答同样在末尾追加引用。
- 边界：跨课程不引用；无课程上下文不引用；资料不足时明确说明，不编造来源。

## 5. 关键流程

### 5.1 登录鉴权

    用户 → 前端登录页 → POST /api/auth/login
      → 按用户名或邮箱查用户
      → PBKDF2 校验密码；停用账号返回 403
      → 签发 JWT {sub, role, exp}
      → 前端写入 localStorage
      → Axios 请求拦截器追加 Authorization: Bearer <token>
      → 401 时清除本地态并跳转登录；403 提示无权限

### 5.2 学习进度

    学生打开课程详情 → GET /api/courses/{id}/progress
      → 首次学习创建 learning_records
      → PUT /api/courses/{id}/progress 提交 chapter_id 与 minutes
      → 已完成章节写入 completed_chapters，study_minutes 累加
      → progress = 已完成章节数 / 总章节数 × 100
      → 返回进度、时长、已完成章节列表

### 5.3 AI 答疑与 RAG

    请求 → 校验 JWT → 获取/创建会话
      → 取最近 10 条消息作为上下文
      → 按 course_id 检索课程资料 Top-3
      → 组装 System Prompt（课程、章节、资料）
      → 有 Key 调 LLM；失败或无 Key 调 Mock
      → 若命中资料，回答末尾追加引用
      → 写入 ai_messages 并返回 mode（online/mock）

### 5.4 订单状态机

    pending ──► paid ──► refunded
       │
       └──► cancelled

    仅允许上述流转；同状态幂等返回；非法流转返回 409。
    无真实支付通道，订单由演示数据产生。

### 5.5 通知生成

    收藏课程更新 / 课程下架 / 学习停滞 7 天
      → 生成 notifications 记录
      → dedup_key 唯一约束保证幂等
      → SSE /api/notifications/stream 每 15s 推送未读数
      → EventSource 主通道；断线保留 60s 轮询兜底；支持单条/全部已读

## 6. 安全设计

| 威胁 | 措施 |
|---|---|
| 密码泄露 | PBKDF2-SHA256，120,000 次迭代，16 字节随机盐；`hmac.compare_digest` 比对 |
| Token 盗用 | JWT HS256，默认 7 天有效期；HTTPS 由部署层负责；401 统一跳登录 |
| 越权访问 | `require_role` + 资源归属校验；教师只能改本人课程；管理员接口 403 兜底 |
| SQL 注入 | SQLAlchemy ORM 参数化；不拼接 SQL 字符串 |
| XSS | 前端 Markdown 渲染前用 DOMPurify 净化；限制输入长度 |
| 参数注入 | Pydantic 字段校验：长度、枚举、分页上限 |
| 敏感配置 | `.env` 不入库；Dockerfile 不复制 `.env`；`.gitignore` 忽略根 `.env` |
| 演示凭据 | 演示账号密码 `123456` 仅用于课堂；生产必须更换并移除 `demo_code` |
| CORS | 通过 `CORS_ORIGINS` 白名单配置；生产按实际域名收紧 |

## 7. 性能与可扩展性

- 索引：课程筛选/排序字段、外键、唯一约束均建索引；列表分页限制 `page_size ≤ 50`。
- RAG：只检索当前课程资料，单课程 5–10 段，内存计算成本低；不引入向量库，保持离线可跑。
- AI：LLM 超时 60s；失败自动 Mock；前端展示模式标识。
- 缓存：当前未引入 Redis；课程列表/字典可后续加 TTL 缓存。
- 扩展：接口按模块拆分，新增社区等可在对应 Router 内扩展；SSE 已落地，MySQL 连接池由 SQLAlchemy 默认管理。
- 前端：ECharts 按需引入，Element Plus 全量引入（855 kB），已拆分 chunk。

## 8. 部署架构

### 8.1 开发环境

- 后端：`uvicorn app.main:app --port 8000`（无 `--reload` 的演示方式；开发可临时加）。
- 前端：`npm run dev`，Vite 5173，`/api` 代理到 127.0.0.1:8000。
- 数据库：默认 SQLite；切 MySQL 时改 `DATABASE_URL`。

### 8.2 Docker Compose

    浏览器 :8080
      → nginx:1.27-alpine（静态 dist + /api 反代）
      → backend:8000（python:3.14-slim）
      → mysql:8.0（volume mysql_data）

- `mysql`：utf8mb4、`mysql_native_password`（兼容 pymysql）、healthcheck。
- `backend`：依赖 mysql healthy；`docker-entrypoint.py` 仅在 `users` 表为空时执行 seed，避免重启覆盖数据。
- `nginx`：托管宿主预构建 `frontend/dist`；history 路由回退；`/api` 反代。
- SSE：响应头 `X-Accel-Buffering: no` 关闭 nginx 缓冲；前端 EventSource + 60s 轮询兜底。
- 端口：`8080:80`；可通过 `HTTP_PORT` 覆盖。
- 环境变量：`MYSQL_*`、`DATABASE_URL`、`JWT_SECRET`、`LLM_*`、`CORS_ORIGINS`、`SEED_ON_START`、可选 `BUILD_HTTP_PROXY`。
- 已有数据补课程资料：`docker compose exec backend python seed_materials.py`（会写库，需确认）。
- 前端重建：先 `cd frontend && npm run build`，再 `docker compose up -d --build`。

### 8.3 运行前提

- Docker Desktop + WSL2；本机缺少 WSL2 时 Docker Linux 引擎无法启动。
- 前端镜像不执行容器内 npm 构建，依赖宿主 dist；新环境必须先构建前端。
- 生产环境需配置 HTTPS、真实 JWT Secret、数据库密码与 LLM Key。

## 9. 可观测性与测试

- 健康检查：`GET /api/health` 返回 `database=up` 与 `llm_mode=mock/online`。
- 日志：Uvicorn 访问日志 + 应用异常日志；当前未接入集中式日志/追踪。
