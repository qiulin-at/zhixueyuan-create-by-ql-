## 2. 项目背景与目标

### 2.1 背景

高校课程学习场景中，课程资源、学习进度、答疑与就业信息分散在不同系统：学生需要在多个平台之间切换，学习路径不清晰，提问后等待时间长，课程内容与岗位要求脱节。平台将课程学习、实习就业与 AI 学习助手整合到同一套账号体系下，并用课程资料检索增强答疑的可信度。

### 2.2 目标

| 目标 | 说明 | 衡量标准 |
|---|---|---|
| 业务闭环 | 选课 → 学习 → 收藏 → 进度 → 报告 | 学生可完整走通学习链路 |
| 教学管理 | 课程上下架、讲师管理、用户与订单管理 | 管理员与教师后台可用 |
| AI 赋能 | 答疑、学习路径、作业批改、学习报告四类能力 | 无 Key 时 Mock 可用，答疑带课程资料引用 |
| 工程规范 | 前后端分离、RESTful、可测试、可部署 | 50 项测试通过、覆盖率 90%、Docker 健康检查 200 |
| 数据可信 | 课程资料可追溯 | 答疑末尾输出「参考：课程 + 章节」 |

### 2.3 干系人

| 干系人 | 关注点 | 影响 |
|---|---|---|
| 学生 | 选课、学习、答疑、就业 | 核心用户 |

| 管理员 | 平台运营、用户与订单 | 管理者 |

### 4.3 核心用例

**UC-01 学生学习课程**

- 参与者：学生
- 前置条件：已登录
- 主流程：进入课程列表 → 选择技术体系/等级/免费 → 按评分排序 → 打开详情 → 收藏 → 完成章节 → 查看进度与学习报告
- 异常流：未登录收藏跳转登录并回跳；课程已下架时详情 404；重复收藏不产生重复记录

**UC-02 AI 课程资料答疑**

- 参与者：学生
- 前置条件：已登录，已选择课程
- 主流程：输入问题 → 后端按当前课程检索资料 Top-3 → 注入 System Prompt → 在线模型或 Mock 生成回答 → 回答末尾追加「参考：课程 + 章节」 → 同一会话继续追问保持上下文
- 异常流：无 LLM Key 或调用失败 → Mock 回答；课程无资料 → 正常回答但不追加引用；跨课程提问不引用其他课程资料

**UC-03 管理员管理课程与订单**

- 参与者：管理员
- 前置条件：管理员 JWT
- 主流程：后台统计 → 新建课程 → 添加章节 → 编辑/上下架 → 查看订单 → 标记已支付 / 退款
- 异常流：删除有学习记录或订单的课程返回 409；非法订单流转返回 409；非管理员访问 403

**UC-04 教师维护本人课程**

- 参与者：教师
- 前置条件：教师 JWT
- 主流程：创建课程（归属本人）→ 编辑课程与章节 → 上下架本人课程
- 异常流：修改他人课程 403；调整课程归属 403（仅管理员）

## 6. 数据需求

核心实体共 14 张表：`users`、`courses`、`chapters`、`favorites`、`learning_records`、`comments`、`orders`、`ai_conversations`、`ai_messages`、`jobs`、`job_applications`、`notifications`、`password_reset_codes`、`course_materials`。

演示数据基线：课程 18 门、章节 90 个、职位 8 个、用户 5 个、订单 1 笔、课程资料 20 条（4 门课各 5 段）。课程与职位均为脱敏演示数据，不包含真实个人信息。

数据约束：

- 收藏、学习记录：同一用户同一课程唯一。
- 评价：同一用户同一课程唯一，重复提交转为更新。
- 职位申请：同一用户同一职位唯一。
- 通知：`(user_id, dedup_key)` 唯一，保证事件幂等。
- 订单号唯一；订单状态只允许合法流转。
- 演示库与测试库分离：测试使用 `backend/tests/test_zhixueyun.db`。

## 7. 约束与假设

- 技术约束：Python 3.14 后端、Vue 3 + Vite 前端、RESTful JSON、SQLite/MySQL 双库兼容。
- 环境假设：演示环境具备网络；LLM Key 可留空，四类 AI 功能自动走 Mock。
- 部署假设：Docker 演示需要 WSL2 与 Docker Desktop；前端镜像使用宿主 `npm run build` 产物。
- 数据假设：课程、职位、订单、课程资料均为演示数据，不涉及真实支付与真实用户隐私。
- 范围约束：不做真实支付、短信、向量数据库、服务端 SSE 推送；学习社区仅保留课程评价。
- 版权约束：课程资料为项目组自写演示文本，不复制教材原文。
