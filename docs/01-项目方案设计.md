# 项目二：面向教育平台的智能体开发 —— 项目方案设计

> 课程：基于 Python 的 AI 项目实践（华为 ICT 学院）
> 团队：4 人（PM / 前端 / 后端 / AI / 测试运维）
> 技术基线：FastAPI + Vue3 + MySQL + OpenAI 兼容大模型
> 文档版本：v1.0（2026-11）

---

## 1. 项目概述

### 1.1 项目背景

本项目面向智慧教育场景，构建一个"课程学习 + 实习就业 + AI 学习助手"一体化的在线教育平台。平台覆盖**理论课程、实训课程、认证课程、实习就业**四大业务模块，为普通学生、教师、管理员三类角色提供差异化能力，并通过大模型实现智能答疑、学习路径推荐、作业批改、学习报告四类 AI 功能。

### 1.2 建设目标

| 目标 | 说明 | 衡量标准 |
|---|---|---|
| 业务闭环 | 选课 → 学习 → 收藏 → 进度 → 报告 | 学生可完整走通学习链路 |
| 教学管理 | 课程上下架、讲师管理、用户与订单管理 | 管理员后台可用 |
| AI 赋能 | 4 个 AI 功能真实可用 | 无 Key 时 Mock 降级，演示不中断 |
| 工程规范 | 前后端分离、RESTful、可部署 | 提供启动脚本与接口文档（/docs） |

### 1.3 范围说明

**本期范围（P0/P1）**：用户系统、课程资源模块、AI 学习助手（答疑 / 路径 / 报告）、基础后台管理、职位列表与详情（只读）。

**本期不做（P2 加分项，按进度取舍）**：学习社区完整版、移动端 App、通知推送服务端推送、在线支付。

| F1-5 | 角色体系 | student / teacher / admin 三角色，接口级权限校验 |

**F2 课程资源模块（P0，基础必做）**

| 编号 | 功能 | 说明 |
|---|---|---|
| F2-1 | 多维筛选 | 技术体系（人工智能/大数据/云计算/工业软件/数通/通信/鸿蒙）、技术方向、课程等级（初级/中级/高级/专业共建）、是否免费 |

| F2-3 | 搜索 | 课程名、讲师名关键词模糊搜索（LIKE） |
| F2-4 | 课程详情 | 封面、简介、目录（课件/视频/实验）、讲师、评分、评论数 |

| F2-6 | 学习与进度 | 开始学习、章节完成打点、进度百分比持久化 |

**F3 实习就业模块（P1，基础必做的一部分）**

| 编号 | 功能 | 说明 |
|---|---|---|
| F3-1 | 职位筛选 | 按职位分类（技术/产品/设计/运营/市场/人事财务行政/高级管理） |
| F3-2 | 职位搜索 | 职位名 / 公司名关键词，支持"职位/公司"切换 |
| F3-3 | 职位详情 | 薪资、城市、公司信息、岗位职责、任职要求 |
| F3-4 | 职位操作 | 收藏、申请职位（申请记录落库） |

**F4 AI 学习助手（P1，进阶必做）**

| 编号 | 功能 | 说明 | 降级策略 |
|---|---|---|---|
| F4-1 | 智能答疑 | 绑定课程的上下文问答，多轮对话，知识点拓展 | Mock 模板回答 |
| F4-2 | 学习路径推荐 | 基于学习记录与目标，生成分阶段学习计划 | 规则模板生成 |
| F4-3 | 作业自动批改 | 提交代码/答案，AI 给出评分、问题定位与修改建议 | 关键词静态规则评分 |
| F4-4 | 学习报告 | 汇总周/月学习时长、进度、薄弱点，输出结构化报告 | 数据库统计 + 模板 |

**F5 加分项（P2，进度富余时做）**

- G1 学习提醒：收藏课程更新、学习计划到期通知（站内信轮询）
- G2 学习社区：课程评论、问答区、点赞
- G3 移动端适配：响应式布局（Element Plus 栅格 + 媒体查询）
- G4 通知推送：WebSocket 或轮询
- G5 订单信息展示：个人中心显示订单

### 2.3 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 列表接口 P95 < 500ms（10 万课程量级下建索引）；AI 接口首字延迟 < 3s（流式） |
| 安全 | 密码 PBKDF2 加盐哈希；JWT 鉴权；接口按角色鉴权；SQL 注入防护（ORM 参数化）；AI 输出 HTML 转义 |
| 可用性 | 大模型不可用时自动降级 Mock；异常统一返回 JSON 错误码 |
| 可维护性 | 分层架构（router → service → model）；配置外置 .env；日志分级记录 |
| 兼容性 | Chrome/Edge/Firefox 最新版；1366×768 及以上分辨率 |

## 3. 技术选型

| 层次 | 选型 | 版本基线 | 选型理由 |
|---|---|---|---|
| 后端框架 | FastAPI | 0.115+ | 异步高性能、自动生成 OpenAPI 文档（/docs）、Pydantic 校验 |
| ORM | SQLAlchemy 2.x | 2.0+ | 成熟稳定，SQLite/MySQL 双兼容，便于本地开发与生产切换 |
| 数据库 | MySQL 8.0（开发可 SQLite） | 8.0 | 指导书要求企业级数据库；SQLite 保证样板开箱即跑 |
| 鉴权 | PyJWT + PBKDF2 | — | 轻量无编译依赖，避免 passlib/bcrypt 在新 Python 版本的兼容问题 |
| 大模型 | OpenAI 兼容协议 | — | 一套代码兼容 DeepSeek / 通义千问 / 智谱 / Moonshot / 盘古 MaaS |
| HTTP 客户端 | httpx | 0.27+ | 异步调用 LLM，超时与重试可控 |
| 前端框架 | Vue 3 + Vite | 3.5 / 5.x | 组合式 API、构建快、生态成熟 |
| UI 组件 | Element Plus | 2.8+ | 教育平台常用，表格/筛选/分页开箱即用 |
| 状态管理 | Pinia | 2.x | Vue3 官方推荐，替代 Vuex |
| 路由 | Vue Router 4 | 4.x | 路由守卫实现登录拦截 |
| 请求库 | Axios | 1.x | 拦截器统一注入 Token、统一错误提示 |
| 图表（报告页） | ECharts | 5.x | 学习时长/进度可视化 |
| 测试 | pytest + httpx TestClient | — | 接口级自动化测试 |
| 部署 | Docker Compose + Nginx | — | 一键起 MySQL/后端/前端静态站 |

## 5. 数据库设计

### 5.1 ER 关系概览

```
users 1 ──── n favorites n ──── 1 courses
users 1 ──── n learning_records n ──── 1 courses
users 1 ──── n orders n ──── 1 courses
users 1 ──── n comments n ──── 1 courses
courses 1 ──── n chapters
users(teacher) 1 ──── n courses
users 1 ──── n ai_conversations 1 ──── n ai_messages
users 1 ──── n job_applications n ──── 1 jobs
users 1 ──── n notifications
```

### 5.2 核心表结构

**users 用户表**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK AI | 用户 ID |
| username | VARCHAR(50) UNIQUE | 登录名 |
| email | VARCHAR(120) UNIQUE | 邮箱 |
| hashed_password | VARCHAR(255) | PBKDF2 哈希 |
| nickname | VARCHAR(50) | 昵称 |
| avatar | VARCHAR(255) | 头像 URL |
| major | VARCHAR(100) | 专业 |
| role | VARCHAR(20) | student/teacher/admin |
| is_active | TINYINT | 是否启用 |
| created_at | DATETIME | 注册时间 |

**courses 课程表**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | 课程 ID |
| title | VARCHAR(120) | 课程名称 |
| cover | VARCHAR(255) | 封面图 URL |
| course_type | VARCHAR(20) | theory/practice/certification |
| tech_system | VARCHAR(30) | 人工智能/大数据/云计算/工业软件/数通/通信/鸿蒙 |
| tech_direction | VARCHAR(30) | 语音识别/图像识别/数据分析/数据可视化/Python/前沿技术… |
| level | VARCHAR(20) | beginner/intermediate/advanced/co_build |
| is_free | TINYINT | 是否免费 |
| price | DECIMAL(10,2) | 价格 |
| teacher_id | BIGINT FK | 讲师 |
| intro | VARCHAR(500) | 一句话简介 |
| description | TEXT | 课程详情 |
| objective | TEXT | 学习目标（JSON 数组字符串） |
| rating | DECIMAL(2,1) | 平均评分 |
| rating_count | INT | 评价人数 |
| study_count | INT | 学习人数 |
| status | VARCHAR(20) | draft/published/offline |
| created_at | DATETIME | 上架时间 |

索引：`(course_type, status)`、`(tech_system)`、`(tech_direction)`、`(level)`、`(study_count)`、`(rating)`、`title` 前缀索引。

**chapters 课程目录表**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | 章节 ID |
| course_id | BIGINT FK | 课程 |
| title | VARCHAR(150) | 章节名 |
| content_type | VARCHAR(20) | video/doc/lab |
| duration_min | INT | 时长（分钟） |
| sort | INT | 排序 |

**favorites 收藏表**：id、user_id、course_id、created_at，唯一索引 `(user_id, course_id)`。

**learning_records 学习记录表**：id、user_id、course_id、progress（0–100）、last_chapter_id、study_minutes、updated_at，唯一索引 `(user_id, course_id)`。

**orders 订单表**：id、order_no、user_id、course_id、amount、status（pending/paid/refunded）、created_at。

**comments 评论表**：id、course_id、user_id、rating（1–5）、content、created_at。

**ai_conversations 会话表**：id、user_id、course_id（可空）、title、created_at。

**ai_messages 消息表**：id、conversation_id、role（user/assistant）、content、created_at。

**jobs 职位表**：id、title、category、company、salary、city、address、headcount、description、requirement、status、created_at。

**job_applications 投递表**：id、user_id、job_id、status（applied/interview/offer/rejected）、created_at。

**notifications 通知表**：id、user_id、type、title、content、is_read、created_at。

### 5.3 MySQL DDL 示例（courses）

```sql
CREATE TABLE courses (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  title VARCHAR(120) NOT NULL,
  cover VARCHAR(255) DEFAULT '',
  course_type VARCHAR(20) NOT NULL DEFAULT 'theory',
  tech_system VARCHAR(30) NOT NULL DEFAULT '',
  tech_direction VARCHAR(30) NOT NULL DEFAULT '',
  level VARCHAR(20) NOT NULL DEFAULT 'beginner',
  is_free TINYINT NOT NULL DEFAULT 1,
  price DECIMAL(10,2) NOT NULL DEFAULT 0,
  teacher_id BIGINT,
  intro VARCHAR(500) DEFAULT '',
  description TEXT,
  objective TEXT,
  rating DECIMAL(2,1) NOT NULL DEFAULT 5.0,
  rating_count INT NOT NULL DEFAULT 0,
  study_count INT NOT NULL DEFAULT 0,
  status VARCHAR(20) NOT NULL DEFAULT 'published',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_type_status (course_type, status),
  KEY idx_system (tech_system),
  KEY idx_direction (tech_direction),
  KEY idx_level (level),
  KEY idx_study (study_count),
  KEY idx_rating (rating)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 6. AI 智能体设计

### 6.1 LLM 网关（双模式）

```
业务请求 ──► AIService
               │
               ├─ 有 LLM_API_KEY ──► httpx POST {LLM_BASE_URL}/chat/completions
               │                       model / temperature / messages / max_tokens
               │                       失败重试 1 次 → 仍失败则降级 Mock
               │
               └─ 无 Key 或调用失败 ──► MockEngine（规则/模板引擎）
```

关键设计：
- **配置驱动**：`LLM_API_KEY`、`LLM_BASE_URL`（默认 `https://api.deepseek.com/v1`）、`LLM_MODEL`（默认 `deepseek-chat`）。
- **统一入口**：`LLMGateway.chat(messages, temperature, max_tokens) -> str`，业务层不感知厂商。
- **多轮上下文**：答疑按 `conversation_id` 取出最近 10 条消息，拼接课程上下文（课程简介 + 当前章节）后送入模型。
- **降级兜底**：Mock 引擎基于问题关键词（HDFS/MapReduce/索引/Prompt…）返回结构化答案模板，保证无网络/无 Key 演示流畅。
- **安全**：System Prompt 约束不输出违法内容；输出经 Markdown 渲染前做 HTML 转义；用户输入长度限制 2000 字符。

### 6.2 四类 AI 功能的 Prompt 设计

**F4-1 智能答疑（多轮）**

```
System：
你是「智学云」平台的 AI 学习助教，当前课程：《{course_title}》
课程简介：{course_intro}
当前章节：{chapter_title}
要求：
1. 用中文回答，先给结论再给解析，控制在 300 字内；
2. 涉及代码时给出可运行示例；
3. 每次回答末尾追加「📌 知识点拓展：」一句话延伸；
4. 不确定的内容明确说明，不要编造。
```

**F4-2 学习路径推荐**

```
输入：用户已学课程与进度、薄弱方向、目标岗位/证书、每周可投入时长
输出：Markdown 表格（阶段 | 周期 | 学习内容 | 对应课程 | 验收标准）+ 总计建议
约束：最多 4 个阶段，优先复用平台已有课程
```

**F4-3 作业自动批改**

```
输入：题目描述、语言、学生代码
输出 JSON：{ "score": 0-100, "dimension_scores": {...},
             "issues": [{"line": n, "severity": "...", "suggestion": "..."}],
             "summary": "..." }
约束：只点评可验证的问题；不执行代码
```

**F4-4 学习报告生成**

```
输入：统计周期内学习时长、完成课程数、进度变化、答题正确率
输出：Markdown 报告（本周概览 / 学习亮点 / 薄弱点分析 / 下周建议）
兜底：无 Key 时由 mock_engine.py 用统计规则 + 模板生成
```

### 6.3 RAG 扩展（作为答辩加分亮点）

1. 课程资料（PPT/讲义）切片（500 字/片，重叠 50 字）→ 向量化（text-embedding）→ 存向量库（Chroma/Milvus）。
2. 答疑时先检索 Top-3 片段，拼入 System Prompt 作为"课程资料参考"。
3. 回答末尾给出引用来源（章节名 + 页码），降低幻觉、提升可信度。

## 7. 关键流程

### 7.1 登录鉴权时序

```
用户 → 前端登录页 → POST /api/auth/login {username, password}
  → 后端校验用户 + PBKDF2 验证密码
  → 签发 JWT {sub: user_id, role, exp: 7d}
  → 前端存 localStorage，Axios 拦截器附加 Authorization: Bearer <token>
  → 访问受保护接口时 deps.get_current_user 解析校验，角色不满足返回 403
```

### 7.2 智能答疑时序

```
学生提问 → POST /api/ai/chat {conversation_id?, course_id?, message}
  → 校验登录；无会话则创建（标题取首问前 20 字）
  → 落库 user 消息
  → 组装上下文：System(课程/章节) + 最近 10 条历史 + 本次问题
  → LLMGateway.chat() → 真实模型或 Mock
  → 落库 assistant 消息
  → 返回 {conversation_id, answer}
```

### 7.3 学习进度计算

```
用户完成章节 → PUT /api/courses/{id}/progress {chapter_id}
  → 统计该课程已学章节数 / 总章节数 × 100 → progress
  → upsert learning_records，累加 study_minutes
  → 返回最新进度；前端进度条即时刷新
```

## 10. 测试与部署

### 10.1 测试策略

| 层级 | 工具 | 覆盖目标 |
|---|---|---|
| 接口测试 | pytest + httpx TestClient | 注册登录、课程筛选排序、收藏、AI 答疑（Mock）主路径 |
| 前端自测 | 手工用例 + 浏览器 | 五大页面主流程、空态/错误态 |
| 性能 | Locust（可选） | 课程列表 50 并发 P95 < 500ms |
| 安全 | 手工 + Bandit（可选） | 越权访问、SQL 注入、Token 过期 |

### 10.2 部署方案

```yaml
# docker-compose.yml 结构（实施阶段落地）
services:
  db:      mysql:8.0        # volume 持久化，初始化 DDL
  backend: build ./backend  # uvicorn app.main:app --host 0.0.0.0
  frontend: nginx:alpine    # 挂载 dist 静态资源 + /api 反代 backend:8000
```

- 开发环境：后端 `uvicorn app.main:app --reload`，前端 `npm run dev`（Vite 代理 /api）。
- 演示环境：Docker Compose 一键起，提供内网访问地址（如 `http://10.0.0.8:8080`）。

## 12. 风险与对策

| 风险 | 概率 | 影响 | 对策 |
